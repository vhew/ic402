# ic402 v2.5.0 — multi-token EIP-712 settlement fix

ic402 v2.5.0 is out — mops `ic402`, npm `@ic402/client` and `@ic402/mcp`.

## The headline: settlement now keys off the paid asset

`Gateway.verifyPayment` already resolved the EIP-712 domain from the asset the payer signed for — but `settle` and `Sessions.openEvmSession` took the verifyingContract, domain, and on-chain execution token from `chain.tokens[0]`. On a chain configured with **more than one token**, a valid EIP-3009 signature for a non-first token would verify, then be rejected or mis-executed at settle.

The fix threads the paid asset through the payment path: `PaymentSignature` gains an optional `asset : ?Text` field — the EVM token contract (the EIP-712 verifyingContract) the payer signed for — and `settle` / `openEvmSession` now key their domain and on-chain execution off it. Two new pure, tested Gateway helpers, `resolveEvmAsset` (asset ?? first configured token) and `resolveEvmDomain` (name/version keyed on the actual token), are the shared seam across verify / settle / openEvmSession.

Blast radius: single-token-per-chain deployments (the shipped config) were unaffected, and no path moved funds on a failed verify.

## Also: an internal robustness and quality pass

Shared-helper extractions and dead-code removal across the library, SDK, MCP server, scripts, and the reference demo — Gateway/EvmSender RPC-preamble and candid-decode helpers, MCP response routing through `textResult`/`serialize`, a shared script PATH-sanitize helper, the SDK's `candid.ts` opt/byte decoders, and the demo client's new `codec.ts` + `evm.ts` (collapsing two ~120-line pasted EIP-712 blocks). No behavior change.

New Motoko + TypeScript tests cover the touched seams: `resolveEvmAsset` / `resolveEvmDomain`, the `consumeVoucher` streaming-charge fund gate, the MCP call-guard case matrix, and the demo codec helpers — including a **pinned EIP-712 signing vector** with an ecrecover round-trip that proves the extracted signer is byte-identical to the old inline blocks.

## Upgrade notes

Fully backward-compatible. `asset` is an optional Candid field — old clients omit it, it decodes to `null`, and the chain's first configured token is used (the prior behavior). No wire/HTTP or `@ic402/client` breaking changes, and `STABLE_SCHEMA_VERSION` stays at `1`, so an in-place upgrade from v2.4.x needs no state migration.
